== About

An event-driven ATM (Automated Teller Machine) simulator in C++.
It consists of three components that never block each other:

* link:{url-src}/include/interface_handler.hpp[`interface_handler`] talks
to the user.
* link:{url-src}/include/machine.hpp[`c_machine`] holds the ATM logic.
* link:{url-src}/include/bank_handler.hpp[`bank_handler`] talks to the bank.

The handlers run each call through `std::async` and return a `std::future`.
The ATM logic keeps handling events instead of waiting for a reply.

The state machine moves through these steps:

. It waits for a card.
. It reads a 4-digit PIN one digit at a time.
. It asks the bank to verify the PIN.
An incorrect PIN ejects the card and returns to the first step.
. It waits for the user to withdraw 50, display the balance, or cancel.
A withdrawal waits for the bank, then issues the cash or reports
insufficient funds.
Cancel ejects the card.

The machine ignores every other input.

The components reach the user and the bank through
link:{url-src}/include/interface.hpp[`interface.hpp`] and
link:{url-src}/include/bank.hpp[`bank.hpp`].
link:{url-src}/src/main.cpp[`main.cpp`] reads the keyboard, and
link:{url-src}/src/driver.cpp[`driver.cpp`] turns each key into an event.

== Build

[,sh]
----
cmake -S . -B build
cmake --build build
./build/src/atm
----

== Usage

[cols="1,3"]
|===
|Key |Action

|`i` |Insert a card
|`0`-`9` |Enter a PIN digit
|`w` |Withdraw 50
|`b` |Display the balance
|`c` |Cancel and eject the card
|`q` |Quit
|===

The test account accepts PIN `1234`.
A sample session looks like this:

[,text]
----
Please enter your card (i)
i
Please enter your PIN (0-9)
3412
PIN incorrect
Ejecting card
Please enter your card (i)
i
Please enter your PIN (0-9)
1234
Withdraw 50? (w)
Display Balance? (b)
Cancel? (c)
w
Issuing 50
b
The balance of your account is 50
c
Cancelled
Ejecting card
Please enter your card (i)
q
----
